# CashPulse — Master Implementation Plan

> **Project**: CashPulse — Lending Intelligence Engine for UBL Relationship Managers  
> **Context**: Hackathon project. Backend-first approach using FastAPI (Python).  
> **Strategy**: 5 phases, backend-driven, with a Next.js (React) frontend that talks to the API. Each phase is independently testable before moving to the next.

---

## Guiding Principles

1. **Backend First** — All business logic lives in FastAPI. The frontend is just a consumer.
2. **No Black Boxes** — Every score must expose `reason` and `evidence[]` in the API response.
3. **Config-Driven Scoring** — Thresholds and weights live in `scoring_config.json`, not hardcoded.
4. **Explainability = Auditability** — Every assessment is persisted with its full input features and evidence so it can be reconstructed at any time.
5. **Synthetic Data Only (MVP)** — No real PII. Realistic-looking PKR transaction data generated by a seeder script.

## Phase Overview

### Phase 0 — Environment Setup
**Goal**: Get every developer's machine ready to run the project in <30 minutes.
- Install Python 3.11+, MongoDB, create virtual environment
- Install all pip dependencies
- Configure `.env` with DB connection, JWT secret
- Verify all services start without errors
- **Deliverable**: `01-environment-setup.md` (full setup guide)

### Phase 1 — Foundation, Auth & Seed Data
**Goal**: A running FastAPI server with a seeded database and working login.
- Define all MongoDB collections (users, smes, transactions, assessments)
- Pydantic models for every collection
- `POST /api/auth/login` → JWT token
- Synthetic data seeder: 10 SMEs × 6 months of realistic PKR transactions
- `GET /api/smes` and `GET /api/smes/{id}` → returns SME data
- **Deliverable**: Server starts, login works, portfolio list returns data

### Phase 2 — Feature Engineering + Scoring Engine
**Goal**: Given an SME's transaction history, compute a full scored assessment.
- Feature engineering service: derive all financial indicators from raw transactions
- Scoring engine: 5 pillars with transparent business rules
- Each pillar returns `{score, max, reason, evidence[]}`
- Readiness Score = weighted sum
- `POST /api/assessments` triggers this pipeline
- **Deliverable**: Calling the API returns a full scored assessment object

### Phase 3 — Eligibility + Recommendation Engine
**Goal**: Translate scores into an actionable recommendation with amount and reason.
- Eligibility engine: safe repayment capacity calculation
- Recommendation engine: Approve / Counter-offer / Manual Review logic
- Full `assessment` object saved to MongoDB
- **Deliverable**: Assessment response includes `recommendation` with `type`, `amount`, `reason`, `evidence`

### Phase 4 — Full API, Chart Data & Report
**Goal**: Complete all REST endpoints and enrich responses with chart-ready data.
- `GET /api/assessments/{id}` — full assessment for the dashboard
- Chart data: 6-month cashflow series (for the bar/line chart)
- `POST /api/assessments/{id}/decision` — RM records their final decision
- Portfolio summary enriched with latest readiness per SME
- **Deliverable**: All endpoints described in `api.md` are implemented and tested

### Phase 5 — Frontend Integration + Polish
**Goal**: A working, beautiful web app that matches the mockup prototype.
- Convert the `mockups/cashpulse-prototype.html` into a real Next.js application (App Router)
- Wire all screens to the live API (login, portfolio list, assessment flow, dashboard)
- Render real chart data using Chart.js
- Full responsive polish (mobile sidebar, etc.)
- **Deliverable**: End-to-end working demo: login → portfolio → assessment → dashboard → decision

## Data Flow Diagram

```
[RM logs in] → POST /api/auth/login → JWT cookie
      ↓
[Views portfolio] → GET /api/smes → list of SMEs with last readiness
      ↓
[Starts assessment] → POST /api/assessments {smeId, requestedLoan, requestedTenure}
      ↓
[Backend pipeline]
  ├── Fetch last 6 months of transactions for smeId
  ├── Feature Engineering Service → derived indicators
  ├── Scoring Engine → 5 pillar scores + readiness (0-100)
  ├── Eligibility Engine → safeCapacity, recommendedAmount
  ├── Recommendation Engine → Approve / Counter-offer / Manual Review
  └── Persist full assessment to MongoDB → return assessment object
      ↓
[Dashboard] → GET /api/assessments/{id} → renders all scores, charts, recommendation
      ↓
[RM Decision] → POST /api/assessments/{id}/decision {decision, note}
```
